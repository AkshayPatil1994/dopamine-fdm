# Examples

← [Home](Home.md)

Three runnable cases live under `examples/`, each a self-contained `input_parameters`
(and, for the IBM case, a geometry). Copy a case's directory contents next to the
`dopamine` executable (or point `filein`/paths at it), create the output directories
(see [Installation § Running](Installation.md#running)), and launch with `mpirun`.

## `les_chan395`

A canonical **wall-resolved LES channel flow** at $Re_\tau \approx 395$.

- `nx,ny,nz = 66,65,66`, `Lx,Ly,Lz = 6.0,2.0,2.0`, `grid_type = 2` (symmetric tanh)
- `nu = 1/395`, `dPdx = 1.0` — non-dimensionalised so $u_\tau = 1$, $H = 1$
- `sgs_model = 1` (Vreman LES)
- `ic_type = 5` (inverse-linear profile to accelerate transition — see
  [Numerics § Initial conditions](Numerics.md#12-initial-conditions))
- Fixed `dt = 1.0`, `nsteps = 120000`
- Periodic in $x$ and $z$ (`x_bc_type = 0`, default)

This is the reference case to validate a fresh build against — compare resulting
mean-velocity and Reynolds-stress profiles against Moser–Kim–Mansour DNS data (see
`postProcessing/analyse_channel.py` in
[Pre- and Post-Processing Tools](Tools.md#analyse_channelpy)).

## `dns_ibm_wavyWall`

A **DNS over a rough (wavy) wall** using the ghost-cell IBM, reproducing ERCOFTAC Classic
Collection Case 076 "Flow over a wavy wall" (Buckles, Hanratty & Adrian, *J. Fluid Mech.*
1984; $Re_H = U_b H/\nu = 6760$).

- `nx,ny,nz = 258,129,130`, `Lx,Ly,Lz = 4.0,1.05,2.0`, `grid_type = 6` (roughness
  sublayer + tanh)
- `sgs_model = 0` (DNS), `x_bc_type = 0` (periodic), `ibm_input_mode = 1` (SDF-based
  ghost-cell IBM, reading the precomputed cell-centre SDF `ibm_sdf_file = 'SDF_in'`)
- `nsteps = -10` — negative, so the run is driven by `sim_end_time` rather than a fixed
  step count (see [Numerics § Stopping criteria](Numerics.md#33-stopping-and-save-interval-criteria))

The bottom-wall geometry is generated by `geo/generate_wavy_wall.py`, which builds a
closed, watertight STL for the sinusoidal wall:

$$\frac{y - y_0}{a} = \cos\!\left(\frac{2\pi x}{\lambda} + \text{phase}\right), \qquad \frac{2a}{\lambda} = 0.10$$

(height-to-wavelength ratio per the Case 076 spec). Feed the resulting STL to `GenSDF`
(`geo/parameters.in` is a ready-made `GenSDF` config for this geometry) to produce the
`SDF_in` the solver reads — see
[Pre- and Post-Processing Tools § GenSDF](Tools.md#gensdf).

For validation results (mean velocity and Reynolds stress profiles against DNS) from
this exact case, see
[Numerics § IBM Validation](Numerics.md#63-validation--turbulent-flow-over-a-wavy-wall).

## `precursor_successor`

Demonstrates **precursor–successor coupling**: a periodic "precursor" simulation
generates fully-developed turbulence, whose planes are recycled as a time-resolved
inflow for a downstream "successor" simulation with an inflow/outflow streamwise BC.
Both cases share the same domain size (`nx,ny,nz = 130,65,66`, `Lx,Ly,Lz = 12.0,2.0,6.0`,
`grid_type = 2`) and LES setup (`sgs_model = 1`).

- **`precursor/`** — a standard periodic channel (`x_bc_type = 0`, `dPdx = 1.0`,
  `ic_type = 1`), run with `nsteps = -200` (i.e. to `sim_end_time`) while writing plane
  slices to `slices/precursor*` for the successor to consume.
- **`successor/`** — `x_bc_type = 1` (inflow/outflow), `dPdx = 0.0` (no imposed mean
  gradient — the inflow carries the momentum), and `inflow_recycle_file =
  '../precursor/slices/precursor'` with `inflow_recycle_loop = 1` to replay the
  precursor's recorded planes as a time-resolved inlet condition. `ic_type = 1` is set
  but not used for initialisation in this mode.

> This recycling inflow mode (`inflow_type`, `inflow_recycle_file`,
> `inflow_recycle_loop`) is broader than the constant/SEM options documented in
> [Input Parameters § INFLOW](Input-Parameters.md#inflow-optional--used-only-when-x_bc_type--1);
> consult `src/` (`sem.f90` / `boundary_conditions.f90`) or open an issue if the recycle
> workflow needs deeper docs.

**Running order**: run `precursor/` to completion first (so `slices/precursor*` exists
and has enough recorded planes), then run `successor/` from its own directory, pointing
`inflow_recycle_file` at the precursor's output.
